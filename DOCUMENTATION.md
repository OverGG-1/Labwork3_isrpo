# Документация TaskTracker

## 1. Назначение
TaskTracker - расширение для Visual Studio Code, которое находит в файлах проекта маркеры `TODO`, `FIXME`, `BUG` и `HACK`, формирует единый список задач и предоставляет инструменты навигации, фильтрации и сортировки.

## 2. Состав модулей
| Модуль | Ответственность |
|---|---|
| `extension.ts` | Точка входа; регистрация Tree View, команд, наблюдателей файлов и событий редактора. |
| `types.ts` | Общие типы `Task`, `TaskType`, `SortMode`, список типов и порядок приоритета. |
| `scanner.ts` | Выбор правил по расширению файла, разбор текста, декодирование байтов, чтение файла и обработка ошибок. |
| `store.ts` | Хранение задач по URI файла, полное сканирование и точечное обновление. |
| `taskProvider.ts` | Представление задач в Tree View, фильтрация, поиск, сортировка и формирование подсказок. |
| `exclusions.ts` | Исключение каталогов и файлов по настройкам; преобразование glob-шаблонов в регулярные выражения. |
| `fileDecorations.ts` | Значки и цветовые декорации файлов в Explorer. |
| `editorHighlight.ts` | Подсветка строк с задачами в открытых редакторах. |

## 3. Модель данных
`Task` содержит:
- `type` — тип маркера (`TODO`, `FIXME`, `BUG`, `HACK`);
- `text` — текст задачи;
- `uri` — URI исходного файла;
- `relativePath` — путь относительно рабочего пространства;
- `line` — номер строки, начиная с 1.

Основные структуры данных:
- `Map<string, Task[]>` в `TaskStore` группирует задачи по URI файла;
- `Set<TaskType>` в `TaskProvider` хранит активные типы фильтра без дубликатов;
- массивы используются для выдачи, фильтрации и сортировки задач;
- `Map<TaskType, number>` в декораторе Explorer подсчитывает задачи каждого типа.

## 4. Алгоритм сканирования
1. `TaskStore.scanWorkspace()` получает список файлов рабочего пространства через `workspace.findFiles`.
2. Файлы, попадающие под исключения, отбрасываются.
3. Оставшиеся файлы обрабатываются пакетами по 20 элементов.
4. `scanFile()` использует актуальный текст открытого документа либо читает файл через VS Code FileSystem API.
5. Файлы больше заданного лимита пропускаются. Бинарные файлы не передаются парсеру.
6. `parseText()` разбивает текст на строки и выбирает регулярное выражение по типу файла.
7. Для каждого найденного маркера создаётся объект `Task`.
8. Результат сохраняется в `Map`; подписчики получают событие об изменившихся URI.

## 5. Правила распознавания
- Для исходного кода и конфигураций маркер должен следовать за распознаваемым символом комментария.
- Для Typst распознаются `//` и `/* ... */`; символы разметки не считаются комментариями.
- Для обычных текстовых файлов ключевое слово может находиться в любом месте строки.
- Поддерживаются `TODO`, `FIXME`, `BUG`, `HACK`; строчные/смешанные формы принимаются при наличии двоеточия.
- Автор в круглых скобках после ключевого слова допускается.
- Пустое описание заменяется на `(без описания)`.

Расширение не выполняет полноценный синтаксический анализ языков: анализ проводится по строкам и регулярным выражениям.

## 6. Обновление данных
`extension.ts` регистрирует `FileSystemWatcher` для создания, изменения и удаления файлов. Изменения открытого документа также отслеживаются через `onDidChangeTextDocument`. Для уменьшения количества повторных операций используется задержка 400 мс на файл. После события вызывается `TaskStore.updateFile()`.

При изменении состава рабочего пространства запускается полное сканирование. При изменении настроек TaskTracker обновляются подсветки и список задач.

## 7. Интерфейс и команды
Расширение добавляет представление «Задачи» на Activity Bar. Элементы дерева содержат тип, текст, путь и номер строки. Выбор элемента вызывает `tasktracker.openTask`, открывающую файл и выделяющую найденную строку.

Команды:
- `tasktracker.refresh` — полное обновление;
- `tasktracker.filterByType` — выбор типов задач;
- `tasktracker.sortBy` — выбор сортировки;
- `tasktracker.search` — поиск по тексту и пути;
- `tasktracker.clearFilters` — сброс фильтров;
- `tasktracker.openTask` — переход к задаче.

## 8. Настройки
| Настройка | Назначение |
|---|---|
| `tasktracker.excludedFolders` | Имена исключаемых каталогов. |
| `tasktracker.excludedFiles` | Glob-шаблоны исключаемых файлов. |
| `tasktracker.maxFileSizeKb` | Максимальный размер файла в КБ; по умолчанию 1024. |
| `tasktracker.decorateExplorer` | Включение декораций файлов в Explorer. |
| `tasktracker.highlightInEditor` | Включение подсветки задач в редакторе. |

## 9. Обработка ошибок и ограничения
Ошибки чтения отдельного файла не останавливают сканирование всего проекта; сведения записываются в Output Channel «TaskTracker». Пропускаются бинарные и слишком большие файлы. Подсветка в редакторе ограничена документами до 20 000 строк. Бейдж Explorer ограничен двумя символами, поэтому количество свыше девяти отображается как `9+`.

## 10. Сборка и запуск
1. Установить Node.js и npm.
2. В каталоге проекта выполнить `npm install`.
3. Выполнить `npm run compile`.
4. Открыть проект в VS Code и нажать `F5` для запуска Extension Development Host.
5. В тестовом проекте создать комментарии с маркерами и проверить список задач.

Для создания пакета при установленном `vsce` используется `npm run package`.
