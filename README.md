# TaskTracker
> ⚠️ **Использование ИИ.** При выполнении работы использовалась нейросеть Claude (Anthropic): она сгенерировала исходный код плагина. 

Расширение для Visual Studio Code, которое находит в исходном коде комментарии с пометками
`TODO`, `FIXME`, `BUG` и `HACK` и собирает их в одну панель. Задачи можно фильтровать,
сортировать и искать по тексту, а по клику сразу переходить к нужной строке файла.
Работает локально, без сторонних серверов.

## Возможности
- Сканирование всех файлов рабочего пространства и поиск задач в комментариях.
- Определение типа задачи: `BUG`, `FIXME`, `HACK`, `TODO`.
- Для каждой задачи хранятся тип, текст, путь к файлу и номер строки.
- Отдельная панель TaskTracker на боковой панели (Activity Bar).
- Фильтр по типу, сортировка по имени файла, типу или номеру строки, поиск по тексту.
- Переход к строке с задачей по клику: файл открывается, строка выделяется.
- Автоматическое обновление списка при создании, изменении и удалении файлов
  и при наборе текста в открытых документах.
- Подсветка файлов с задачами в Explorer: цвет по самому срочному типу и значок с числом задач.
- Подсветка строк с задачами в редакторе: значок рядом с номером строки,
  мягкий фон строки и метка на полосе прокрутки.
- Поддержка Typst (`.typ`) и любых других текстовых файлов.
- Ошибки чтения файлов не прерывают сканирование и записываются в канал Output «TaskTracker».


## Установка и запуск
```
code --install-extension tasktracker-1.0.0.vsix
```
Либо открыть панель расширений (`Ctrl+Shift+X`), выбрать меню `…` и пункт **Install from VSIX…**.

## Использование
Кнопки в заголовке панели «Задачи» слева направо:

| Кнопка | Действие |
|---|---|
| Поиск | Ввод строки; показываются задачи, у которых текст или путь файла содержит её. Пустая строка сбрасывает поиск. |
| Фильтр | Выбор типов задач, которые нужно показывать. |
| Сортировка | По имени файла, по типу или по номеру строки. |
| Сбросить | Возвращает все типы и убирает строку поиска. |
| Обновить | Полностью пересканирует рабочее пространство. |

Под заголовком показывается число задач (например, «3 из 12»), а также активные фильтры
и текущая сортировка.

Порядок типов при сортировке по типу: `BUG`, `FIXME`, `HACK`, `TODO`.
Вторичные ключи сортировки: при сортировке по файлу, затем номер строки и тип;
при сортировке по типу, затем файл и строка; при сортировке по строке, затем файл и тип.

## Правила распознавания
Расширение не выполняет синтаксический разбор языков. Задача распознаётся по строке целиком.

| Тип файла | Правило |
|---|---|
| Исходный код и конфигурации (`.cpp`, `.h`, `.js`, `.py` и др.) | Перед ключевым словом должен стоять маркер комментария: `//`, `/*`, `*`, `#`, `--`, `;`, `%`, `<!--`. |
| Typst (`.typ`) | Только комментарии `//` и `/* … */`. Разметка `#` и `*жирный*` комментарием не считается. |
| Текстовые файлы (`.txt`, `.md`, `.rst`, `.log`, `.adoc`, `.org`) | Ключевое слово принимается в любом месте строки. |

Ключевые слова пишутся заглавными буквами. Формы `todo:`, `Todo:`, `fixme:`, `bug:`, `hack:`
принимаются, если после слова стоит двоеточие. После слова может идти автор в скобках:

```cpp
// TODO: добавить проверку аргументов
// FIXME(ivan) утечка памяти в парсере
/* HACK временное решение до рефакторинга */
// BUG
```

Строка без текста попадает в список с пометкой «(без описания)».

## Настройки
| Параметр | По умолчанию | Описание |
|---|---|---|
| `tasktracker.excludedFolders` | `node_modules`, `.git`, `.svn`, `.hg`, `.vscode`, `.idea`, `out`, `dist`, `build`, `target`, `venv`, `.venv`, `__pycache__`, `coverage` | Каталоги, которые не сканируются. |
| `tasktracker.maxFileSizeKb` | `1024` | Файлы больше этого размера пропускаются. |
| `tasktracker.decorateExplorer` | `true` | Значок и цвет файлов с задачами в Explorer. |
| `tasktracker.highlightInEditor` | `true` | Подсветка строк с задачами в редакторе. |

Цвета можно изменить через `workbench.colorCustomizations`. Доступны ключи
`tasktracker.bugForeground`, `tasktracker.fixmeForeground`, `tasktracker.hackForeground`,
`tasktracker.todoForeground` и аналогичные `…Background` для фона строки.

```
    ├── store.ts            хранилище задач, сканирование рабочего пространства

```

## Как это работает
1. `TaskStore` получает список файлов через `workspace.findFiles`, исключая служебные каталоги,
   и читает их пачками по 20 файлов.
2. `scanner.ts` пропускает бинарные и слишком большие файлы, поддерживает UTF-16 с BOM
   и разбирает текст построчно регулярным выражением, подходящим для типа файла.
3. Результат хранится по файлам. Любое изменение хранилища оповещает панель задач
   и подсветку файлов в Explorer.
4. Обновление идёт по событиям: наблюдатель за файлами и изменения в открытых документах
   (с задержкой 400 мс) пересканируют только затронутый файл.
5. `TaskProvider` строит плоский список: применяет фильтр по типам и поиск, затем сортирует.
6. `EditorHighlighter` разбирает видимые редакторы напрямую и ставит значки, фон и метки.

## Ограничения
- Полноценный разбор языков не выполняется. Ключевое слово внутри строкового литерала
  после маркера комментария (например, `"# TODO"`) тоже будет найдено.
- API VS Code не позволяет менять цвет самого номера строки, поэтому строки отмечены значком
  рядом с номером, фоном и меткой на полосе прокрутки.
- Значок файла в Explorer ограничен двумя символами, поэтому больше девяти задач показывается как `9+`.
- Файлы в исключённых каталогах и файлы больше `tasktracker.maxFileSizeKb` не сканируются.
